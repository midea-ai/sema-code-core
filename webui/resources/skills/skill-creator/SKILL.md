# 技能制作

技能（Skill）是一个目录加一份 `SKILL.md`：frontmatter 里的 `description` 常驻上下文用于触发判断，正文在技能被调用时注入对话作为工作指引。可以附带脚本和参考资料。

## 存放位置

- 用户级（所有项目可用，**默认放这里**）：`~/.sema/skills/<技能名>/SKILL.md`
- 项目级（仅当前项目，可随仓库共享）：`<项目根>/.sema/skills/<技能名>/SKILL.md`

除非用户明确要求项目级或要随仓库共享，新建技能一律放用户级。

设置了 `SEMA_ROOT` 环境变量时，用户级根目录以它为准。技能的启用/停用记录在对应层级 `settings.json` 的 `disabledSkills` 里，一般不需要手工改。

## 文件格式

```markdown
---
name: my-skill
description: 一句话说清做什么、什么时候用，并列出触发关键词。
---

正文：技能被调用时注入的完整工作指引。
```

约束：
- `name` 与 `description` 必填，且正文不能为空，否则技能不会被加载
- `name` 用小写字母、数字、连字符，并与目录名保持一致
- 同名技能高层覆盖低层：项目级 > 用户级 > 插件

## 创建流程

1. **明确用途**：先问清三件事——什么场景下该触发？输入是什么？期望产出是什么？
2. **规划结构**：
   - 纯指引类：单个 `SKILL.md` 即可
   - 有可复用脚本：放 `scripts/`，正文写明确切的调用命令
   - 有长篇参考资料（规范文档、模板、示例）：放 `references/`，正文只写"何时读哪个文件"
3. **写 description**（决定触发准确率，最值得打磨）：
   - 用第三人称写"做什么 + 什么时候用"
   - 列出用户可能说出口的触发词，包括中英文叫法
   - 避免只写功能名词；要写出使用场景
4. **写正文**：
   - 保持精炼（建议 500 行以内），按默认流程分步骤写
   - 细节、边界情况、长示例拆到 `references/`，需要时再读（渐进式披露）
   - 脚本用相对技能目录的路径引用，不要写死绝对路径
5. **验证**：开一个新会话，用目标场景的说法提问，确认技能被触发且步骤可执行；再用一个不相关的问题确认不会误触发。

## 常见问题

| 症状 | 原因与修法 |
| --- | --- |
| 该触发时不触发 | description 太笼统，补场景描述和触发词 |
| 不该触发时触发 | description 范围过宽，收窄"什么时候用"并写明"不适用于什么" |
| 技能没被加载 | frontmatter 缺 name/description，或正文为空，或目录层级不对 |
| 上下文被撑爆 | 正文塞了全部细节，拆到 references/ 按需读取 |

## 优化已有技能

先定位问题属于哪一类：触发问题改 description，执行问题改正文步骤，知识问题补 references/。每次只改一处并重新验证，避免一次改多处无法归因。
